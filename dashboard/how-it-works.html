How It Works

LegacyFlow Orchestrator uses IBM Bob 2.0 as a full orchestration engine — not just a coding assistant. Plan mode creates a structured plan with a human approval gate. The --yolo flag bypasses the gate for automated demo runs. Parallel subagents execute concurrently and structured outputs are written automatically.

System Architecture
5-Stage Orchestration Pipeline
1
Bob Plan mode
Plan Phase — Bob reads the codebase and creates a structured execution plan
Bob is invoked with bob -p .legacyflow/project-template/ --yolo. In Plan mode, Bob reads INSTRUCTIONS.md and scans the codebase structure, then produces a detailed execution plan listing which files to analyse, which patterns to search for, what output files to write, and in what order. This plan is visible in the Plan tab of the Results Viewer for full transparency.
2
🔐 Approval Gate
Human Approval Gate — The governance checkpoint before any execution
Bob's Plan mode is designed to pause here and present the plan to a human before executing. This is the governance and safety checkpoint: a reviewer can inspect the proposed actions, reject the plan, or approve it. In production use, this gate provides auditability and change control — no automated tool writes to your codebase without a human sign-off.

In LegacyFlow's demo mode, the --yolo flag bypasses this gate, allowing fully automated runs. This is safe here because all codebase access is read-only — the only writes are structured output files in the isolated project directory. The plan is still written to plan.md for auditability.
3
Parallel subagents
Parallel Subagents — Two Bob agents execute concurrently
Bob spawns two independent subagents via spawn_subagent.

Agent 1 — Impact Analysis skill: Traces the target field across every RPG, CLLE, and copybook file. Counts read sites, write sites, conditional branches, batch job references, and shared copybook definitions. Produces a call chain diagram and a complete reference breakdown per file.

Agent 2 — Business Rules Extraction skill: Reads source code semantically to catalogue validation rules, state transitions, threshold constants, and guard clauses. Detects duplicate rule implementations across files and flags them for consolidation.

Both agents work simultaneously in their own isolated contexts, reducing total runtime by approximately 50% vs. sequential execution.
4
Synthesis
Risk Scoring & Effort Estimation — Cross-agent synthesis
After both agents complete, Bob synthesises the results. Risk score (1–10) is computed across seven evidence-based factors:

+Complexity: Files referencing field  ·  Branching logic count  ·  Write site count  ·  Batch job involvement  ·  Shared copybook definition  ·  Duplicate rule count
−Deduction: Centralised validation exists (reduces score — this is the "good news" factor)

Bob then calculates effort per file — manual analysis hours vs. LegacyFlow-assisted hours — with a reference-count breakdown for constants, writes, reads, and conditional logic per file.
5
Structured output
Output Files — Written to the project directory, immediately dashboard-ready
All 6 outputs land in .legacyflow/projects/<project-id>/ and are immediately viewable in the Results Viewer.
impact-report.md
Full field reference map, call chain diagram, change recommendations
business-rules.md
Extracted rules catalogue, state machine diagram, rule table
risk-score.json
Machine-readable score with per-factor breakdown and rationale
effort-estimate.json
Hours with/without tooling, file-by-file reference counts
plan.md
Bob's execution plan — the approval gate document
audit-trail.md
Complete log of every phase, decision, and action taken
Why the approval gate exists
In enterprise modernization projects, governance is non-negotiable. The approval gate means an engineer reviews exactly what actions Bob will take before any execution occurs. It creates a clear audit trail and prevents unintended side effects — the same reason code review exists.
--yolo in the demo
--yolo is an IBM Bob 2.0 flag that auto-approves the Plan mode gate. It's appropriate here because the INSTRUCTIONS.md is carefully authored so the plan is deterministic and safe — all codebase access is read-only. LegacyFlow uses it intentionally; a production deployment would require human approval.
