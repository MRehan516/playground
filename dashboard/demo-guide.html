Demo Guide

A step-by-step walkthrough for presenting LegacyFlow Orchestrator at a hackathon or customer demonstration.

Pre-demo checklist: The demo project 20260829-demo-cust-status is pre-loaded with all 6 output files. For a static demo (no live run), just open dashboard/index.html in a browser — no server needed. For a live run demo, start the Flask backend first with python server.py from the workspace root.
Static Demo Path (Recommended)
1
Open the Home page
Navigate to dashboard/index.html. Point out the hero section — the value proposition is clear: "AI-driven intelligence for IBM i modernization." The demo callout shows real numbers from the pre-loaded run: Risk 9/10, 6 files, 31 code references, 49 business rules, 120–180h saved.
2
Explain the sidebar navigation
The persistent left sidebar shows this is a real internal tool, not a single page. Point out the sections: Main (Home, Projects), Analysis (Impact Analysis, Business Rules), Learn (How It Works, About, Demo Guide). This demonstrates that LegacyFlow is designed for ongoing team use, not just a one-off script.
3
Open the Projects page
Click Projects / Runs in the sidebar. The stats bar shows aggregate metrics across all runs. The project card shows the risk badge (red ring with "9"), workflow type pill, files, rules count, and status badge. Click the card to open the viewer.
4
Walk through the Results Viewer tabs
The viewer has 6 tabs — walk through them in order:
Summary tab
Lead with this. Show the 6 metric cards: Risk Score (9/10 in red), Files Affected (5), Rules Extracted (49), Code References (31), Hours Saved, Est. Hours w/ Tool. The "Recommended Actions" section shows the first action highlighted in blue with a "Start here" label — this tells the team exactly what to do next. The Output Files section proves structured, usable artefacts were produced.
Impact Report tab
Show the Call Chain SVG diagram — it visually demonstrates the system understood the program architecture. Point out the green STATVLD box (the authoritative validation API that already exists) and the dashed copybook inclusion lines. Then scroll down to the risk analysis and recommendations.
Business Rules tab
Show the State Machine SVG — 4 states, color-coded transitions, and the dashed red "✗ blocked" line showing the forbidden Active→Closed direct transition. This is a business rule Bob discovered by reading the source code. Scroll down to the rules catalogue table (49 rules).
Risk & Effort tab
Show the factor breakdown table with the CSS bar charts. The "Weight" column visually conveys which factors contributed most to the 9/10 score. Then show the per-file reference table with the "Refs" bar chart — CUSTMAST.rpg clearly has the most work to do.
Audit Trail tab
Show the timeline view. This demonstrates transparency — every phase Bob executed is documented with bullets and key decisions. This is the kind of audit trail enterprise teams need for governance and sign-off.
Live Run Demo Path (Flask Backend)
1
Start the Flask backend
From the workspace root: python server.py. The backend starts on localhost:5000 and serves the dashboard at http://localhost:5000/dashboard/.
2
The Run Panel appears automatically
When the Flask backend is running, a "Run new analysis" panel appears on the Projects page — populated with fields from the sample codebase (CUSTCP.rpgleinc). Select a field and click "Run Analysis". The panel shows a live progress timeline with animated phase steps.
3
Bob runs live
The backend spawns bob -p … --yolo as a subprocess. The status endpoint polls every 2 seconds. When complete, the project card list automatically refreshes and a "View results" link appears in the progress panel.
Talking points: Emphasise that this is all running locally — there's no cloud dependency. The AI (IBM Bob 2.0) reads the actual source code, reasons about it, and writes structured outputs. The dashboard is entirely static HTML — no React, no build step, no dependencies beyond a CDN Markdown renderer. The whole system is transparent and auditable.
